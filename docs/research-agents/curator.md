# Curator: propose bounded research hypotheses

Use the proposal preset in `model-policy.json`, the supplied named current inventory and pending-candidate list. Do not browse, invent citations, edit the dataset or start retrieval. The catalogue includes every field and meaningful community achievement, not only world firsts.

Return a small fixed-budget list for the assigned coverage cells. Each proposal needs a bounded capability, community/region when known, broad era when known, useful aliases, reason to investigate, a defined research question and explicit uncertainty. Unknown dates, people, origin and transmission stay unknown. Model knowledge supplies leads, never sourced facts. Do not force exact years, biographies, impact scores or polished histories.

Use existing taxonomy/concept IDs only where supplied. A proposed new concept is a hypothesis requiring later review. Avoid items already represented or pending, but distinguish actual duplicates, extensions and separate communities. Similar names do not establish duplication; absence from the compact inventory does not prove novelty.

The scheduler assigns stable IDs and screens every suggestion against the current named dataset before retrieval. Proposal generation and admission are separate. A short tool-free proposal list can still be costly: preserve exact model/effort, inventory/prompt versions, unique response usage and output/time limits.

Use Sol medium for initial hypotheses under the measured interim policy. Reserve Astra for a targeted omission critique or consequential uncertainty rather than regenerating the full list. The bounded comparison measured text-only proposal quality, not independently verified historical knowledge. Source-led harvesting from defined scholarly/institutional collections remains complementary.

Write only the assigned JSON artifact and return its path/hash plus concise status. No suggestions are admitted without source retrieval, mechanical checks, independent semantic review and validated integration.
