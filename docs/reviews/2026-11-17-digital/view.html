Added · Arm Scalable Vector Extension2016-08-22

arm-scalable-vector-extension

Arm designed a vector instruction set extension for AArch64 in which processors can implement vector lengths from 128 to 2,048 bits in 128-bit steps. The design allows vector-length-agnostic software to run across those choices without recompilation. Per-lane predicates control which elements take part in an operation.

Arm added a 64-bit execution state, AArch64, to its application processor architecture alongside the 32-bit AArch32 state. AArch64 introduced the A64 instruction set, with fixed 32-bit instruction encodings and 64-bit general-purpose registers.

Changed fields · research

Findings

  • Arm's public preview of Armv8-A was in October 2011. Its first non-confidential A64 overview followed on 11 November. The SVE design used a portion of that A64 instruction encoding. [d2-fugaku-arm-2014-armv8a-history; d2-fugaku-arm-2011-a64-overview; d2-fugaku-stephens-2016-a64-sve-encoding]
  • Arm's Hot Chips 28 deck dates the public design account of the Scalable Vector Extension to 22 August 2016. The supported design range is 128–2,048 bits in 128-bit increments; the specific A64FX width was 512 bits. [d2-fugaku-stephens-2016-sve; d2-fugaku-stephens-2017-sve-paper; d2-fugaku-yoshida-2018-a64fx]
  • Fujitsu's Hot Chips 30 disclosure on 21 August 2018 and RIKEN's 18 November 2019 prototype report document distinct stages. The latter reports 768 A64FX chips in the Numazu prototype. [d2-fugaku-hot-chips-30-programme; d2-fugaku-yoshida-2018-a64fx; d2-fugaku-riken-2019-prototype]
  • Alappat et al. report 0.5 cycles per standard SVE ld1d instruction as reciprocal throughput in their FX1000 microbenchmark. Diehl et al. separately ran a stellar-merger code with SVE on up to 1,024 Fugaku nodes. [d2-fugaku-alappat-2021-a64fx; d2-fugaku-diehl-2023-octo-tiger]
  • Watanabe et al. report about 1.7 µs on TofuD for a four-byte message with 24 threads in their multiworker UCX setup using six interfaces, four completion queues and zero-copy optimization. Their comparison is between software implementations on TofuD. [d2-fugaku-watanabe-2024-tofud-benchmarks]

What still needs evidence

  • Seek an FX100 and Fugaku implementer with direct evidence of transfer of named Tofu2 routing, virtual-torus mapping or remote-memory operations. Paired tests alone can corroborate the feature match; documentation of carryover is still needed.
  • Arm's 2011 overview documents compatibility with earlier A32/T32 instructions. To follow an earlier generation, compare the Armv7-A architecture reference manual with the 2011 preview and distinguish inherited 32-bit compatibility from the design sources of AArch64.

Evidence limits

  • Source search through 17 November 2026. Public disclosure dates do not date first working silicon or the beginning of ISA design. The FX1000 instruction test and the Fugaku application scaling run have different scopes. Independent tests support implementations; they do not establish priority or a lineage through Tofu2.
